## Изменение объёма против спеки

Проба расширена решением PM. Три пункта, ранее вынесенные за скобки, вернулись:

| Было | Стало | Следствие |
|---|---|---|
| сравнение КП не проектируем | сравнение в объёме | отдельный экран, логика сопоставления разнородных КП |
| кабинет мебельщика не делаем, WhatsApp + форма по ссылке | личный кабинет | авторизация, две роли, сессии |
| карточки предзаполняем мы | **гибрид: предзаполняем мы, мебельщик правит** | самозаполнение делаем, но на старте от него не зависим |

**Объём:** ~10 экранов + авторизация вместо четырёх экранов.
**Срок до Gate 1:** ориентировочно две–три недели вместо одной.
Общий горизонт с прогоном — около пяти недель, не двух.
Риск принят PM осознанно и повторно подтверждён.

## Треки

### A · Люди и контент — маркетолог
**Критический путь. Стартует первым, зависит от чужой доброй воли.**

| | Работа | Готово, когда |
|---|---|---|
| A1 | Набрать 7 мебельщиков: пост в Instagram Asia Mebel + личные контакты | 7 согласий на карточку, 3+ на приём заявок |
| A2 | Собрать материал и **предзаполнить карточки** самим | 7 карточек с описанием и портфолио |
| A3 | Договориться о приёме: кто, часы, кто дежурит вечером и в выходные | письменная договорённость с каждым |
| A4 | Скрипт квалификационного звонка: достройка заявки + 2–3 вопроса на будущее | скрипт на одну страницу |

Без 3+ мебельщиков на приёме эксперимент не запускается: оффер обещает
предложения, которых не будет.

### B · Фронт — PM, вайбкод

| | Работа | Примечание |
|---|---|---|
| B1 | Главная-каталог + карточка мебельщика | главная страница продукта |
| B2 | Лендинг | ТЗ из чата, + ссылка в каталог |
| B3 | **Форма заявки, вопросы по категориям** | главная правка к ТЗ, см. спека §3 |
| B4 | Страница КП клиента + сравнение | сравнение включается от двух КП |
| B5 | Кабинет мебельщика: заявки, форма КП, профиль | правка предзаполненной карточки |

**B3 — самое ценное.** «Сколько метров вдоль стены», картинки вместо ЛДСП.
Это ядро: переживает эксперимент и переезжает в следующую версию.
Остальной фронт — оболочка, помечена к удалению, см. спека §1.3.

### C · Бэкенд — разработчик

| | Работа | Примечание |
|---|---|---|
| C1 | Модель данных: заявка, КП, мебельщик | **ядро, переживает пробу** — делать как продукт |
| C2 | Авторизация: клиент по OTP, мебельщик через кабинет | две роли |
| C3 | Маршрутизация заявки троим + уведомления | SMS клиенту, WhatsApp/Telegram мебельщику |
| C4 | События воронки и таблица наблюдения | без этого эксперимент не измеряется |
| C5 | Хранение ПДн, согласие | условие валидности теста и требование закона |

### D · Трафик — маркетолог

| | Работа | Примечание |
|---|---|---|
| D1 | Креативы, два оффера под A/B | развести обещания с лендингом, см. спека §7 |
| D2 | Кампания, таргет по районам новостроек | не один ЖК: алгоритму нужен объём показов |

Не стартует раньше B1/B2 и C4 — иначе трафик льётся в неизмеряемую страницу.

## Зависимости

```
A1 ──→ A2 ──→ B1 (каталог без карточек пустой)
A1 ──→ A3 ──→ GATE 1
C1 ──→ C2 ──→ B3, B4, B5  (фронт ждёт модель данных и роли)
C4 ──→ D2                 (без аналитики трафик лить нельзя)
B1, B2 ──→ D2
```

**Двойной критический путь:** A1 — набор мебельщиков, самый неуправляемый срок.
C1–C2 — модель данных и авторизация, от них зависит весь фронт. Оба стартуют первыми.

---

## GATE 1 · Готовность к запуску

Трафик не включается, пока не выполнено всё:

- [ ] 3+ мебельщика подтвердили приём заявок, известно кто дежурит вне рабочих часов
- [ ] Каталог не пустой: 7 предзаполненных карточек
- [ ] Сквозной проход вручную: заявка → мебельщик → КП → клиент увидел
- [ ] Аналитика пишет события воронки
- [ ] Согласие на обработку ПДн стоит под формой, политика опубликована
- [ ] Скрипт квалификационного звонка готов, дежурный на дозвон назначен

## Прогон · 14 дней

**Ежедневно:** проверка воронки, вмешательство на разрывах — заявка неполная ·
мебельщик молчит больше суток · клиент не открыл КП двое суток.

### Точка 1 · день 3
**Вопрос:** прошла ли хоть одна заявка весь путь до КП?
**Нет** → трафик на паузу, чиним поток. Тест не должен мерить нашу неготовность.

### Точка 2 · день 7
**Вопрос:** сколько квалифицированных заявок и по какой цене?
**Меньше 3** → меняем оффер или таргет, один раз. Дальше по светофору.

## GATE 2 · Разбор

Сверка с критериями из `experiment-spec.md` §1.1 по трём звеньям.

| Звено | 🟢 | 🟡 | 🔴 |
|---|---|---|---|
| Приток | 15+ заявок, ≤ 3 300 ₸ | 5–14 | < 5 |
| Мебельщик | 60%+ КП за 48 ч | 30–59% | < 30% |
| Клиент | 50%+ открыли, 30%+ контакт | открывают, не выходят | не открывают |

**Решение:** продолжаем · чиним и повторяем один раз · останавливаемся.

При 🔴 на звене 1 выбрасывается всё, включая построенный контур КП —
цена решения «строить сразу», принятая осознанно.
При 🟢 оболочка переписывается, ядро (модель данных, формулировки формы,
дизайн-система, каталог) переезжает.

## Открытые вопросы

| Вопрос | Владелец |
|---|---|
| Оценка бэкенда в днях → сроки всего плана | разработчик |

## Чего этот эксперимент не ответит

Дойдёт ли заявка до сделки — цикл мебели 3–8 недель, тест до неё не доживёт.
На 15 заявках это проверка существования сигнала, а не статистика рынка.
